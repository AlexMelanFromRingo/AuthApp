# Quickstart: збірка та валідація

## Передумови

- JDK 17, Android Studio (актуальний стабільний), Android SDK 35
- Node.js 20+, npm
- Python 3.11+ із пакетом `blake3` (лише для регенерації тестових векторів)
- Пристрій/емулятор Android 8.0+ з налаштованою біометрією (для ручних сценаріїв)

## Команди

```bash
# 1. Тестові вектори (одноразово або після зміни generate.py)
python3 shared/test-vectors/generate.py     # оновлює shared/test-vectors/*.json

# 2. Криптоядро Kotlin: усі вектори мають пройти (SC-001, SC-002)
cd android-app && ./gradlew :core-crypto:test

# 3. Збірка додатка
./gradlew :app:assembleDebug                # APK у app/build/outputs/apk/debug/

# 4. Web-стенд: тести та dev-сервер
cd ../web-stand && npm ci
npm test                                    # Vitest на тих самих векторах
npm run dev                                 # http://localhost:5173

# 5. Продакшн-збірка стенду (деплой на GitHub Pages — через Actions)
npm run build                               # статика у dist/
```

## Сценарії валідації (мапа на критерії успіху)

1. **SC-001/SC-002 — вектори**: кроки 2 і 4 вище завершуються без падінь;
   у звіті тестів 0 skipped.
2. **SC-003/SC-004 — демо-цикл TOTP**: відкрити стенд → задати алгоритм
   (по черзі всі 7) → відсканувати QR додатком → ввести код із додатка на
   стенді → «збігається». Повторити з digits=9 для BLAKE3-256.
3. **SC-005 — OCRA**: стенд → режим OCRA → згенерувати виклик → відсканувати
   на екрані OCRA додатка → ввести відгук на стенді → «валідний»; повторне
   введення того самого відгуку → «відхилено».
4. **SC-006 — міграція**: додаток A: експорт 3 токенів (парольна фраза) →
   додаток B (друга інсталяція/емулятор): сканування кадрів, імпорт →
   квитанція → додаток A: сканування квитанції → деактивація → токени на A
   не генерують кодів, на B коди збігаються зі стендом.
5. **SC-007 — захист секретів**: `adb backup` порожній
   (allowBackup=false); скріншот екрана кодів заблоковано (FLAG_SECURE);
   `adb logcat` під час усіх сценаріїв не містить секретів/кодів;
   без проходження BiometricPrompt список токенів недоступний.
6. **SC-008 — сумісність стенду**: відкрити продакшн-URL у Chrome і Firefox
   (дві останні мажорні версії), пройти сценарії 2–3.
