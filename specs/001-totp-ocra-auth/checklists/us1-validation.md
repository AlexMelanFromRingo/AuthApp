# Валідація US1: додавання токена та генерація TOTP-коду

**Статус**: пройдено на пристрої 2026-06-09 (крім перезавантаження)

Сценарії приймання зі spec.md (US1):

- [x] 1. Перший запуск: доступ надається лише після успішної біометричної перевірки
- [x] 2. Сканування QR (SHA-1, 6 цифр, 30 с) зі стенду → токен у списку, код збігається з еталонним
- [x] 3. Токен із секретом RFC 6238 (`GEZDGNBVGY3TQOJQGEZDGNBVGY3TQOJQ`, SHA-1, 8 цифр): у відомий момент часу код = еталонному значенню вектора
- [x] 4. Тап по коду → код у буфері обміну + сповіщення «Код скопійовано»
- [x] 5. QR із BLAKE3-256 і 9 цифрами → токен додається, генерує код заявленої довжини
- [ ] 6. Перезавантаження пристрою → токени доступні після біометрії, секрети ніде не у відкритому вигляді — НЕ ПЕРЕВІРЕНО

Додатково (edge cases):

- [x] Відмова в дозволі камери → пояснення, без аварійного завершення
- [x] Непідтримуваний QR (сміття, v=2, закороткий секрет) → україномовна помилка
- [x] Повторне сканування того самого QR → діалог «замінити чи додати окремо»

## Результати

Прогін 2026-06-09 на фізичному пристрої: всі сценарії пройдено, крім п. 6
(перезавантаження — відкладено). Виявлений під час прогону дефект сканера
(зупинка доставки після першого помилкового QR) виправлено того ж дня.
