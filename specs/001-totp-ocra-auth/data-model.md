# Data Model: Комплекс засобів аутентифікації (TOTP/OCRA)

**Дата**: 2026-06-09 | **Джерело**: spec.md (Key Entities) + research.md

## Перелік алгоритмів (спільний словник)

Канонічні ідентифікатори, однакові в Kotlin, JS, URI та тестових векторах:

| Ідентифікатор | MAC-конструкція | Довжина MAC, Б | Усічення |
|---------------|-----------------|----------------|----------|
| `SHA1`        | HMAC            | 20             | RFC 4226 (нібл) |
| `SHA256`      | HMAC            | 32             | RFC 4226 (нібл) |
| `SHA512`      | HMAC            | 64             | RFC 4226 (нібл) |
| `SHA3-256`    | HMAC            | 32             | узагальнене (FR-009) |
| `BLAKE2S-256` | keyed-режим     | 32             | узагальнене (FR-009) |
| `BLAKE2B-512` | keyed-режим     | 64             | узагальнене (FR-009) |
| `BLAKE3-256`  | keyed-режим     | 32             | узагальнене (FR-009) |

Конвенція довгого ключа: секрет, довший за розмір ключа keyed-режиму,
попередньо хешується тим самим алгоритмом (FR-008).

## Token (Токен / обліковий запис)

Зберігається лише в зашифрованому сховищі додатка (EncryptedSharedPreferences,
ключ запису = `id`). Секрет після додавання ніколи не показується в UI.

| Поле | Тип | Обмеження |
|------|-----|-----------|
| `id` | UUID v4 | первинний ключ, генерується при додаванні |
| `type` | enum `TOTP` \| `OCRA` | обов'язкове |
| `issuer` | String | 1..64 символи; відображається у списку |
| `account` | String | 0..128 символів |
| `secret` | байти (Base32 у URI) | 10..64 Б; непорожній (інакше відмова FR-006) |
| `algorithm` | enum (таблиця вище) | обов'язкове для TOTP; для OCRA — походить із suite |
| `digits` | Int | TOTP: 6..10 (6..8 для стандартних сценаріїв, 9..10 — розширені) |
| `period` | Int (секунди) | TOTP: 15..120, типово 30 |
| `ocraSuite` | String | лише OCRA: парситься, дозволені suites — див. OcraSuite |
| `createdAt` | epoch millis | службове |

**Валідація при імпорті з QR** (FR-006): невідомий `algorithm`, `digits`
поза межами, порожній/некоректний Base32-секрет, незнаний `ocraSuite` →
відмова з україномовним поясненням, токен не створюється.

**Дублікат** (edge case): збіг (`type`,`issuer`,`account`,`secret`) →
діалог «замінити чи додати окремо».

**Стани**: `Active` → (видалення з підтвердженням, FR-004) → видалено;
глобальний перехід усього сховища: `Active` → `Deactivated` (crypto-erase,
FR-019) — незворотний, виконується знищенням майстер-ключа Keystore.

## OcraSuite (підтримувані профілі)

Повна граматика RFC 6287 §6 (FR-013/FR-027, розширено 2026-06-11):
`OCRA-1:HOTP-{SHA1|SHA256|SHA512}-{6|8}:[C-]Q{N|A|H}{04..64}[-PSHA{1|256|512}][-S{nnn}][-T{n}{S|M|H}]`

| Компонент | Допустимі значення | Динамічний вхід |
|-----------|--------------------|-----------------|
| CryptoFunction | HOTP-SHA1/SHA256/SHA512 із 6 або 8 цифрами | — |
| C | опціональний лічильник | 8 Б big-endian; значення передає сервер (параметр `c`) |
| Q | формат N (числовий) / A (буквено-цифровий) / H (hex), довжина 04..64 | виклик; для взаємної автентифікації — конкатенація QC/QS |
| P | PSHA1 / PSHA256 / PSHA512 | хеш PIN; PIN запитується в користувача |
| S | Snnn (nnn — байтів) | сесійні дані (параметр `s`, base64url) |
| T | T{n}{S\|M\|H} | floor(unix_time / крок), 8 Б big-endian |

Коректність підтверджується повним набором векторів RFC 6287 Appendix C
(70 векторів: односторонні, взаємні, підписи) у трьох реалізаціях.

## OcraChallenge (OCRA-виклик; лише пам'ять сесії стенду)

| Поле | Тип | Обмеження |
|------|-----|-----------|
| `cid` | 8 Б випадкових, base64url | одноразовий ідентифікатор |
| `suite` | OcraSuite | з конфігурації стенду |
| `q` | String, 8 цифр | CSPRNG, провідні нулі допустимі |
| `createdAt` | epoch millis | |
| `ttl` | 120 с | константа FR-014 |
| `status` | `ISSUED` → `VALIDATED` \| `EXPIRED` | |

**Переходи**: `ISSUED` → `VALIDATED` (одна успішна валідація; подальші
спроби з тим самим `cid` відхиляються); `ISSUED` → `EXPIRED` (через ttl);
невдала спроба валідації НЕ спалює виклик (дозволяє виправити одруківку),
але прострочення і повтор після успіху — відхиляються (FR-014, FR-023).

## MigrationPackage (Пакет міграції)

| Поле | Тип | Обмеження |
|------|-----|-----------|
| `pid` | 8 Б випадкових, base64url | ідентифікатор пакета, зв'язує квитанцію |
| `version` | Int = 1 | несумісні зміни → інкремент |
| `salt` | 16 Б | для Argon2id |
| `kdfParams` | {m: 65536 KiB, t: 3, p: 4} | зафіксовані в заголовку |
| `nonce` | 12 Б | AES-256-GCM |
| `ciphertext` | байти | AEAD(K_enc, manifest) |

**Manifest** (відкривається лише після розшифрування): масив експортних
записів Token (усі поля, включно з секретом) + `manifestHash` =
SHA-256(канонічна серіалізація). Часткового імпорту не існує: або весь
маніфест пройшов автентифікацію GCM і зберігся, або нічого (FR-017).

**Подання**: серія QR-кадрів (кадр 1 = заголовок: pid, version, salt,
kdfParams, nonce, n; кадри 2..n = фрагменти ciphertext ≤512 Б base64url)
або один файл. Імпортер відстежує бітову карту отриманих кадрів і показує
прогрес (FR-017).

## ImportReceipt (Квитанція імпорту)

| Поле | Тип | Обмеження |
|------|-----|-----------|
| `pid` | base64url | MUST збігатися з pid пакета |
| `mac` | 32 Б base64url | HMAC-SHA256(K_rcpt, manifestHash ‖ nonce) |

Верифікація на старому пристрої: обчислити очікуваний MAC зі свого
manifestHash/nonce/K_rcpt і порівняти константним часом. Успіх → дозволена
штатна деактивація (FR-018); провал/відсутність → лише примусова з
подвійним підтвердженням (FR-019).

## StandConfig (конфігурація стенду; лише сесія браузера)

| Поле | Тип |
|------|-----|
| `mode` | `TOTP` \| `OCRA` |
| `algorithm` / `suite` | зі спільного словника / OcraSuite |
| `digits`, `period` | як у Token |
| `secret` | Base32; введений або згенерований (20 Б CSPRNG) |
| `issuer`, `account` | для підпису QR |

Жодної персистенції: перезавантаження сторінки очищає все (FR-020).

## Похідні ключі міграції (не зберігаються)

```
master = Argon2id(passphrase, salt, m=64MiB, t=3, p=4, len=64)
K_enc  = HKDF-SHA256(master, info="authapp-migration-enc",  len=32)
K_rcpt = HKDF-SHA256(master, info="authapp-migration-receipt", len=32)
```

Обидва ключі існують лише в пам'яті на час операції; після завершення —
зануляються.
